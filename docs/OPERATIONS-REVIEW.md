- **TZ Osijeka:** 10 upserts; six month-only listings lacked exact dates.

- **TZ OBŽ:** five upserts; one outside-city candidate was skipped, HeadOnEast had an incomplete AI response, and one antiquities AI candidate was rejected.

Upserts include updates and are not a count of new public events. Deterministic public events were retained; the public API returned 200 with **23 published events** after the run. The daily tip batch checked **three queued tips**, created **zero drafts**, archived **two** and left **one pending**. The monthly application AI ledger showed **$0.285 against the $1 limit**; this does not verify the provider-side key limit.

The workflow is active and its daily `23 5 * * *` cron is on `main`. Commit `13065ce` introduced that schedule at **05:36 UTC on 3 October**, after the day's 05:23 slot. The first expected scheduled run is **4 October at 07:23 Zagreb (05:23 UTC)**. No scheduled invocation had yet been observed, so scheduler delivery remains unverified despite the successful manual run.

## Confirmed gaps and dispositions

| Priority             | Finding                                                                                                                                            | Action                                                                                                                                                                                                                                      |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1                   | GitHub secret scanning, push protection and Dependabot security updates are disabled in repository metadata.                                       | Recommend enabling the free safeguards available to this public repository. Settings were not changed during this review. A clean one-time scan is not a replacement for ongoing checks.                                                    |
| P1                   | `main` has no branch-protection rule and the repository has no rulesets.                                                                           | Agree the owner's merge/deployment workflow, then require the relevant checks. Do not silently lock out the existing direct-push workflow.                                                                                                  |
| P1                   | Database credentials are configured in preview/development scopes; actual destination isolation is unverified.                                     | Verify integration branching and use an isolated database for previews/development before allowing untrusted or experimental deployments. Do not infer that values are identical from the scope listing alone.                              |
| P1                   | No automated production export, restoration exercise or documented recovery evidence was found in the repository.                                  | Select private backup storage, confirm the actual Neon restore setting, and restore a backup into an isolated database before calling recovery verified. The one-time SQLite-to-Postgres migration is not a recurring backup.               |
| P1                   | Collection errors are visible in source status and process exit status, but no dedicated stale-collection alert destination is configured in code. | Agree an alert destination and test a failed/stale collection without contacting anyone or changing notification preferences during this review. The health endpoint alone is not a collection-freshness check.                             |
| P2                   | Retention periods for archived tips, source snapshots, AI cache and logs are not defined.                                                          | Document retention and deletion rules before implementing cleanup. Preserve current-month AI accounting and publication provenance; do not delete records merely because this review identified the gap.                                    |
| Fixed in this change | Workflow actions used movable version tags and CI/collector checkouts retained credentials.                                                        | Pin all existing action versions to verified upstream commit SHAs, keeping version comments, and set `persist-credentials: false` for the remaining checkouts. No action major-version upgrades or repository-setting changes are included. |

The action SHAs were resolved through the upstream GitHub repositories' commit API for the existing tags, rather than copied from a third-party list. Pinning makes the action reference immutable; it does not audit the pinned action's implementation. [GitHub secure-use guidance](https://docs.github.com/en/actions/reference/security/secure-use).

Neon's current Free-plan documentation advertises a **six-hour instant restore window**. This is a plan capability, not a verified setting or tested recovery guarantee for WagZ; a problem discovered after that window may need a separate backup. [Neon Free-plan update, 2 October 2026](https://neon.com/blog/neon-free-plan-1-gb-per-project).
