# WagZ application security review

Reviewed **3 October 2026**, starting from `097f949`. This is a bounded application review, not security certification or proof that every attack is prevented. At the original review, the fixes below were working-tree changes; that review did not deploy them or change production records, credentials or account settings.

**Deployment follow-up, 3 October:** the reviewed fixes were subsequently committed and are included in production release `219c4e9`. Limited production read checks passed for public pages/API, sitemap/robots, CSP/editor headers and anonymous admin denial; see [deployment evidence](DEPLOYMENT.md). Per-test statements below retain their original snapshot and isolation limits. Live database privileges/concurrency, provider/account controls and the other explicitly unverified risks remain open.

**Pilot closure follow-up, 3 October:** shared failed-authentication/collection quotas, a global public-submission ceiling and complete Origin matching are now implemented and locally verified. The current behavior below supersedes the earlier per-process and host-only limitations. This follow-up changes no production records or credentials; deployment and live Neon validation belong to the release evidence.

**Live isolated Neon verification, 3 October at 09:24 UTC:** two independent Postgres pools used a newly created `wagz_audit_*` schema and a separate advisory-lock key. Twenty concurrent rotating-client submissions admitted exactly 7 for a configured daily ceiling of 7; 45 failed-auth admissions admitted 30; 15 collection admissions admitted 6; 12 concurrent $0.25 reservations admitted 4, totaling exactly $1. A third connection reopened with migrations disabled and all four ceilings remained exhausted. All nine table counts matched expectations, no provider request was made, and the audit schema was removed. Production tables and quotas were untouched. Evidence: `.artifacts/security-neon-audit-report.json`; implementation: `scripts/security-neon-audit.ts`. This validates live transaction/concurrency behavior, not an application attack against production or a separate runtime role's privileges. The earlier SQLite/mocked results below retain their original scope.

The review covers Express authorization and public responses, community submissions, source URL admission, provider response validation, spending reservations and the React administrator/public rendering boundaries. Requirements were informed by [OWASP ASVS 5.0.0](https://owasp.org/projects/asvs), [WSTG](https://owasp.org/www-project-web-security-testing-guide/) and the [REST Security Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html). A checklist reference is not itself test evidence.

All adversarial requests used in-memory or temporary SQLite databases, mock provider responses and synthetic keys. No paid provider calls, production mutations, `.env`/`.env.hosted.local` reads or real browser-profile inspection were performed by this review. Browser tests used a newly created headless Chromium context. Actual Neon concurrency and privileges were not tested; Postgres transaction behavior was checked through the existing mocked adapter tests and code inspection.

## Access and public-data results

**S5. Missing production browser policy — low, defense in depth; fixed locally.** `vercel.json` and the production-only `mountPublicPages` now enforce a matching Content-Security-Policy. It allows same-origin scripts/API requests, Google Fonts stylesheet/font hosts, required inline styles and self/data images. It denies objects, base URL changes and framing, and permits neither inline scripts nor eval. `server/public-pages.test.ts` checks local/hosted policy parity. The built-app browser regression verifies normal workflows and deliberately blocked inline script execution. Development Vite middleware remains outside this production policy.

OpenRouter documents `max_results` as a limit on search results and exposes retrieved excerpts in URL annotations; it does not guarantee one annotation occurrence per result. Deduplicating repeated exact URL/normalized-excerpt pairs is an application inference from that contract, while the distinct-URL and total-character caps remain explicit local safeguards. [OpenRouter web-search contract](https://openrouter.ai/docs/guides/features/server-tools/web-search)

The `server/security.test.ts` route matrix sends **98** isolated requests: seven paths, seven HTTP methods and both missing/wrong credentials. Protected handlers are spied on and database contents are compared before/after. Denials return `401`, switching to `429` after the shared failed-auth threshold. Malformed request bodies may fail earlier in the JSON parser with `400`; no protected handler is reached.

**Passed:** query-string/cookie values cannot authenticate; a missing server key fails closed with `503`; replacing the synthetic runtime key invalidates the old key. Existing functional tests verify authorized settings, collection, preparation, event review and publication. The administrator key is explicitly sent in the authorization header, not automatically supplied by browser cookies.

**Editor entry point:** this release uses `/ured-231b67e86427` and its trailing-slash variant, with no public navigation or sitemap link. Old `/admin` variants return 404 without redirecting. The empty editor shell has no private server-rendered payload and uses no-store/noindex/CSP. The address can be found in client assets/source; the existing bearer-key middleware on every `/api/admin/*` request remains the access boundary. The page change adds no alternate API or authentication bypass.

**Passed:** Origin matching compares the complete normalized scheme/host/port tuple. Empty/opaque/malformed origins, URL credentials, paths, query strings, fragments, a different scheme or port and cross-origin preflights receive `403` before data access. Same-origin and absent-origin native-client requests work. Hosted mode uses configured HTTPS plus the request Host because Vercel terminates TLS; local mode uses the actual socket transport. Forwarded and X-Forwarded-Proto/Host/Port cannot change the expected origin. No permissive CORS response is added. Explicit bearer authentication remains necessary for every admin request. `server/security.test.ts` verifies local and hosted transport cases, including forged forwarding metadata.

**Passed:** `/api/events` includes only upcoming published records; public submissions return only `ok` and a generic message. Submitted `status`, `publication` and `draft` fields cannot publish a tip. API success/error/private responses use no-store; internal exception details do not enter public error bodies. Operational log redaction was not comprehensively audited here.

Public admission requires both five attempts per client per hour and **100 total attempts per UTC calendar day**. Set `WAGZ_TIP_DAILY_LIMIT` to a nonnegative integer to tune the pilot ceiling; zero closes public submissions. Both windows update atomically in the same write transaction. Per-client denials do not consume the global allowance; global denial creates no new client row. Invalid/duplicate submissions that reach the handler count as attempts; malformed JSON and cross-origin requests fail earlier. Thus rotating addresses cannot admit more than the configured daily count. Calendar-day rollover can admit two daily allowances across midnight; this is deliberately a day ceiling, not a rolling 24-hour limit.

Public submission starts no background AI preparation. Each collection run considers at most 20 queued tips, each at most once per Zagreb day, within the collection deadline. The 100/day ceiling bounds incoming growth but can exceed processing throughput during abuse, more so once collection runs twice weekly (branch `claude/post-release-work`); quota tuning and retention remain operational controls. No per-person identity or automatic tip-retention purge is introduced here.

`tip_quotas` retains hashed client/hour windows. New `request_quotas` stores namespaced hashed failed-auth client keys and fixed global keys, attempt counts and expiry timestamps; raw addresses and bearer tokens are never written. SHA-256 hashes are pseudonymous, not irreversible anonymization. Each quota request removes at most 128 expired rows from each relevant table; expired rows never block a fresh window. The global failed-auth ceiling also bounds new address rows. All quota writes participate in the existing SQLite write transaction/Postgres advisory transaction lock. Database failures propagate as generic no-store errors and no submission or collection starts; a valid admin key is checked before failed-auth storage and remains usable when only quota storage is unavailable.

**Migration:** owner-mode initialization adds `public.wagz_request_quotas` and `wagz_request_quotas_expiry` on Postgres (unprefixed SQLite equivalents). With `WAGZ_DATABASE_MIGRATIONS=disabled`, hosted startup checks all required columns and the publication setting in a read-only transaction and never creates tables or writes initial settings. An owner must migrate first; the restricted runtime then fails closed on a missing schema. The release owner applied the additive quota migration, verified the dedicated `wagz_runtime` role's restricted grants, and provisioned it for Vercel plus the GitHub collector/backup secret. The scheduled collector also disables migrations; owner credentials remain local maintenance material. Credential provisioning/deployment evidence belongs to the operations report. The isolated concurrency audit above also passed migration-disabled startup, using its owner connection rather than impersonating that runtime role.

**Passed:** hostile tip/source instructions are serialized as user data, the system prompt identifies them as untrusted, tools-disabled preparation stays tools-disabled, and application/admin credentials are absent from prompt bodies. A mocked plausible result carrying hostile HTML creates an **unverified review draft**, with no public event. These tests validate application boundaries; they do not prove that a live model always classifies adversarial prose correctly or that a cited event is true. Source extraction can publish allowed source imports according to the existing auto-publish setting; human review is mandatory specifically for community tips.

**Passed:** script/data/file/FTP/credential-bearing link schemes are rejected by server validation and browser `safeLink`. No SSRF exploitation was demonstrated, and this review does not certify that provider boundary. Owner: application maintainer/source-provider integration.

**Passed in isolated Chromium:** hostile public titles/descriptions and administrator notes render as literal text, create no injected image/script nodes and trigger no dialogs. No native Flutter rendering or device storage security test was performed in this review.

**Passed locally and in preview HTTP checks; production rollout pending:** the production CSP permits the built app's public/admin pages, submission/review dialogs, source-link popup and both Google Fonts families with no unexpected `securitypolicyviolation` events, page errors or failed font requests. ## Public event page follow-up

**S6. Malformed public URLs bypassed error handling — low, disclosure/header consistency; fixed locally.** `GET /dogadaji/%E0%A4%A` failed during Express parameter decoding before the route's try/catch. Because public routes were mounted after the API error handler, the default 400 HTML lacked no-store/noindex and included a stack trace when `NODE_ENV` was unset, including the local `--production` startup mode. Production Express configuration suppresses the stack but still missed those application headers. A final public-page error handler now returns generic 400/503 text, no-store and noindex while preserving CSP. The regression checks malformed event, asset and root paths without querying real data.

**Passed locally:** the new `/dogadaji/:id` HTML and `/api/events/:id` lookup use a parameterized query and the same explicit public DTO. Draft, rejected and nonexistent IDs return the same generic 404; previously published past events deliberately retain their public link. The upcoming feed and sitemap exclude past/private records. Unpublishing an event takes effect on its next request; neither event data nor 404s are cached by the template cache. HTML, sitemap and API data responses use `Cache-Control: no-store`.

**Passed locally:** metadata is HTML-escaped, React escapes displayed text, and the JSON payload/JSON-LD escape `<`, `>`, `&` and Unicode line separators. Hostile `</script><img ... onerror=...>` and replacement tokens remain text, cannot close the script element, and round-trip through the embedded JSON. Canonical and sitemap URLs use the fixed deployment origin rather than request Host/forwarding headers. Build/database failures return generic 503 responses with no-store and noindex; no empty success fallback is returned. Structured data preserves known date/status/location facts and omits unknown offer/organizer/image information.

The isolated Chrome run also loaded the direct event route, refreshed it, hydrated its server markup and opened its interactive dialog under the unchanged CSP. It observed no injected nodes, execution, hydration errors or unexpected CSP violations. A later run exercises the actual separate Vite SSR bundle and new editor path: `.artifacts/security-browser-1791011788332/report.json`, **14 checks passed**.

**Hosted packaging findings:** the first preview built successfully but function requests returned 500 because Vercel's trace omitted the rewritten `src/App.js` import. The fix emits a self-contained SSR bundle outside public `dist`, includes it explicitly in the function and dynamically imports it there. The second preview served populated HTML and public data. Its trailing-slash editor URL exposed a header-pattern gap: the static shell received default cache headers because Vercel's `/:path*` pattern did not match the empty trailing slash. Explicit slash header rules close that gap; no private data was in the shell. Final preview verification is recorded below.
